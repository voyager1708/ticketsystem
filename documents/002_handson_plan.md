# Django + Google Colab ハンズオン計画（2時間）

## 目的
このハンズオンは、`handson/v1-start` から出発して `Goal` まで到達する過程で、API開発の「設計 -> 実装 -> 検証」を体験することを目的とする。  
題材はチケットシステム（アカウント作成、チケット生成、配布、チェックイン、報酬送付）とする。

---

## 進め方（AI併走）

- まず自分で実装して小さく実行確認する
- 失敗したら、事実（コマンド/入力/エラー）を整理してAIに相談する
- AIの提案はそのまま全採用せず、差分を理解してから反映する
- Stepごとに「成功条件」を満たしたら次に進む

---

## 前提環境（v1-start）
- 実行環境: Google Colaboratory
- フレームワーク: Django
- API実装/検証: Django REST Framework + Swagger UI（drf-spectacular）
- DB: SQLite（学習優先でシンプルに固定）
- 外部連携（Ordinal-X / BSV）: 実APIを利用（Sandbox/検証環境を推奨）
- 開始ブランチ: `handson/v1-start`

---

## 到達目標（Goal）
- DjangoでAPIを作る最小構成（URL, View, JSONレスポンス）を理解する
- 入力バリデーションとエラーレスポンスを設計・実装できる
- 状態遷移を伴うAPI（チェックイン）を実装できる
- Swagger UIから自作APIを検証し、仕様と実装の対応を説明できる
- Ordinal-X 実API連携時の認証・環境変数・エラー処理の基本を理解する
- API提供者の視点で「仕様を決める→実装→検証」を体験する
- 実装内容を自分の言葉で説明できる（AI提案を含む）

---

## 全体タイムテーブル（120分）

### 1. 導入・ゴール確認（10分）
- なぜ「呼ぶ側」だけでなく「作る側」を学ぶのか
- 本日の5APIの全体像を確認
  1) アカウント作成  
  2) チケット生成（テンプレート）  
  3) 配布（チケット画像取得）  
  4) チェックイン  
  5) チェックイン報酬送付

### 2. Colabセットアップ（15分）
- リポジトリ取得
- 依存インストール
- マイグレーション
- Djangoサーバ起動
- DRF + Swagger UI導入（`/api/schema/`, `/api/docs/`）
- Ordinal-X接続設定（`BASE_API_URL`、認証情報、接続確認）
- 動作確認（最小エンドポイントをSwaggerから実行）

### 3. Django APIの型を学ぶ（15分）
- URLルーティングの基本
- View（関数/クラス）とSerializerの基本
- JSONレスポンスの返し方
- バリデーションとHTTPステータスの対応
- Swagger上でのリクエスト/レスポンス確認

### 4. 実装演習（必須3本 + 余裕があれば2本）（70分）
#### 必須API（優先）
1. **アカウント作成API** `POST /accounts`  
   - 入力チェック（必須項目）
   - 201 / 400 の返し分け

2. **チケット生成API** `POST /tickets/templates`  
   - チケットテンプレート作成
   - 201 / 400 の返し分け

3. **チェックインAPI** `POST /tickets/{id}/checkin`  
   - 状態遷移（未チェックイン → チェックイン済み）
   - 404 / 409 などの扱い

#### 余裕があれば実装
4. **配布API** `POST /tickets/distribute`（実API連携）  
5. **報酬送付API** `POST /rewards/send`（実API連携）

#### 各StepでのAI活用（共通）
- 相談前に「再現手順」「期待値」「実際の結果」を1つずつ書き出す
- AIには「次の1手」を質問する（例: 「次に確認すべき設定を3つ」）
- 変更後は必ず同じ入力で再実行し、改善したかを確認する

### 5. 振り返り（10分）
- 設計した要素の再確認（入力、出力、エラー、状態遷移）
- API提供者視点での学びを共有

## 学習用API設計テンプレート（各API共通）
学生には、実装前に以下を記入させる：

1. Endpoint / Method  
2. ユースケース（誰が何のために呼ぶか）  
3. リクエスト項目（型・必須/任意・制約）  
4. 正常レスポンス（HTTPコード + JSON例）  
5. 異常レスポンス（400 / 404 / 409 / 500の条件）  
6. 状態遷移の有無（特にチェックイン）  
7. テスト観点（正常1件、異常2件以上）

AI相談テンプレ:

```text
いま Step X の「<API名>」を実装中です。
再現手順: ...
期待する結果: ...
実際の結果: ...
関連コード: ...
次に確認すべき点を優先度順に3つください。
```

## 進行設計
- 完成版を先に写経せず、`v1-start` のTODOを埋める
- 「全てを深く」より「必須3APIを確実に完成」を優先する
- フォーム画面は作らず、Swagger UIで実装と検証を完結させる
- 最後に必ず自作APIをSwaggerから叩いて検証する

---

## Colab運用の注意
- Colabはセッションが切れるため、こまめに保存する
- `runserver` 常駐セルとSwagger検証セルを分ける
- 依存が重い場合は `requirements-colab.txt` を用意して軽量化する
- APIキーやトークンはノートブックに直書きせず、環境変数で管理する
- 本番環境を使う場合は送信先・対象データを必ずダブルチェックする
